# ПРАВИЛА ИЕРАРХИИ СТРУКТУРНЫХ ЭЛЕМЕНТОВ НПА

## 1. Общие правила

1. Каждый элемент имеет `item_id` - уникальный идентификатор
2. Каждый элемент имеет `item_type` - тип элемента
3. Каждый элемент имеет `item_level` - уровень вложенности (1 для верхнего уровня)
4. Дочерние элементы хранятся в `item_children`
5. Ссылка на дочерний элемент в `body` родителя - блок `child_ref`

## 2. Иерархия уровней

### Для обычных НПА:
1. `chapter` - глава (опционально)
2. `section` - раздел (опционально)
3. `article` - статья
4. `part` - часть
5. `point` - пункт
6. `subpoint` - подпункт
7. `paragraph` - абзац (не имеет `item_children`)

### Для приложений:
1. `appendix` / `nested_appendix` - приложение
2. `article` - статья внутри приложения
3. `part` - часть
4. `point` - пункт
5. `subpoint` - подпункт

### Для структурированных таблиц:
1. `structured_table` - таблица
2. `section` - раздел таблицы
3. `point` - пункт таблицы
4. `subpoint` - подпункт таблицы

## 3. Правила нумерации

### item_number:
- Текущий номер элемента
- Может быть строкой: "1", "1.1", "5.1", "I", "VI¹", "а)", "б)"
- При наличии `number_revisions` - номер из последней действующей ревизии

### number_revisions:
```json
{
  "number_text": "5",
  "valid_from": "01.01.2023",
  "valid_to": "14.03.2025",
  "mod_type": "correction",
  "modified_by_id": "456"
}
```

## 4. Правила создания item_id

### Формат:
`<npa_id>_<item_type>_<item_number>[_double_N]`

### Примеры:
- `123_article_1`
- `123_part_2`
- `123_point_3`
- `123_appendix_1`
- `123_appendix_1_double_1` (для дубля)

### Для элементов внутри structured_table:
- `123_table_1_section_I`
- `123_table_1_point_1`

## 5. Правила работы с body

### Типы блоков body:
1. `paragraph` - абзац текста
   - `html_text`: HTML-код абзаца
   - `order`: порядковый номер
2. `table` - таблица
   - `html_text`: полный HTML таблицы
   - `order`: порядковый номер
3. `child_ref` - ссылка на дочерний элемент
   - `item_id`: ID дочернего элемента
   - `order`: порядковый номер
4. `table_header` - заголовок таблицы (только для structured_table)
   - `html_text`: HTML заголовка
   - `order`: порядковый номер
5. `table_fragment` - фрагмент таблицы (для дочерних элементов structured_table)
   - `html_text`: HTML строк/ячеек
   - `order`: порядковый номер

### Правила порядка (order):
- Всегда последовательный, начиная с 1
- Непрерывный (без пропусков)
- Внутри `body` абзацы, таблицы и `child_ref` чередуются по порядку следования в документе

## 6. Правила работы с revisions

### Активная ревизия:
- `valid_to` = `null`
- Должна быть ровно одна активная ревизия на элемент
- Если активной нет - берется последняя по `valid_from`

### Создание новой ревизии:
1. Найти активную ревизию
2. Установить `valid_to` = (новая_дата - 1 день)
3. Создать новую ревизию с `valid_from` = новая_дата
4. Скопировать `body` из старой ревизии (если не `delete`)
5. Установить `modified_by_id` = ID изменяющего НПА

### Особенности для разных типов изменений:

#### new_redaction:
- Полная замена `body`
- `mod_type` = "new_redaction"

#### delete:
- `body` может быть пустым или содержать старое содержимое
- `mod_type` = "delete"

#### add:
- У нового элемента создаётся ревизия с `mod_type` = "add"
- У родителя создаётся ревизия с `mod_type` = "change"

#### change:
- Изменяется содержимое `body` активной ревизии
- ИЛИ создаётся новая ревизия с изменённым `body`
- `mod_type` = "change"

## 7. Правила для head_revisions

### У каких элементов есть head_revisions:
- `article`
- `chapter`
- `section`
- `appendix`

### Структура:
```json
{
  "head_text": "Статья 1. Общие положения",
  "valid_from": "01.01.2024",
  "valid_to": null,
  "mod_type": "new_redaction",
  "modified_by_id": "456",
  "highlights": {}
}
```

### Изменение наименования:
- `structural_element` = "Статья 3 наименование" или "Наименование" (для всего НПА)
- `type` = "change" или "new_redaction"

## 8. Правила для item_prefix_revisions

### Только у элементов типа `appendix`:
```json
{
  "prefix_text": "Приложение 1",
  "valid_from": "01.01.2024",
  "valid_to": null,
  "mod_type": "new_redaction",
  "modified_by_id": "456"
}
```

### Изменение префикса:
- `structural_element` = "Приложение 1" или "Приложение"
- `type` = "change", "new_redaction" или "delete"

## 9. Правила работы с highlights

### Когда создавать:
- Только для изменений, требующих визуального выделения разницы
- Для `new_redaction` - подсветка добавленного/удалённого текста
- Для `change` - подсветка заменённого текста

### Структура:
```json
{
  "previous_edition": {
    "deletion": [],
    "addition": [],
    "difference": []
  },
  "current_edition": {
    "deletion": [],
    "addition": [],
    "difference": []
  }
}
```

### Правила заполнения:
- `deletion` - текст, который был удалён из старой редакции
- `addition` - текст, который был добавлен в новую редакцию
- `difference` - текст, который был заменён (старый и новый)
- `positions` - координаты в формате "M-N" (M - номер абзаца, N - номер вхождения)
