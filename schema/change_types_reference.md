# СПРАВОЧНИК ТИПОВ ИЗМЕНЕНИЙ НПА

## 1. Общие принципы

Каждое изменение имеет тип (`type`), который определяет, как оно будет применено к целевому НПА.

## 2. Тип `add` (добавление)

### Условия применения:
- Добавление нового структурного элемента, который ранее не существовал
- Должен быть указан `structural_element` (родительский элемент) и поле `new` (тип и номер нового элемента)

### Пример:
```json
{
  "revision_number": "2",
  "structural_element": "Статья 3",
  "type": "add",
  "description": "дополнить частью 3.1 следующего содержания:",
  "new": "часть 3.1"
}
```

### Действие:
1. Найти родительский элемент по `structural_element`
2. Создать новый элемент с типом и номером из `new`
3. Добавить его в `item_children` родителя
4. Добавить `child_ref` в `body` родителя
5. Создать ревизию для нового элемента с `mod_type = "add"`
6. У родителя обновить ревизию с `mod_type = "change"` (добавлен дочерний элемент)

## 3. Тип `delete` (удаление)

### Условия применения:
- Полное удаление структурного элемента
- Должен быть указан полный путь к удаляемому элементу

### Пример:
```json
{
  "revision_number": "2",
  "structural_element": "Статья 5",
  "type": "delete",
  "description": "статью 5 признать утратившей силу"
}
```

### Действие:
1. Найти элемент по `structural_element`
2. Установить `valid_to` активной ревизии = (дата_изменения - 1 день)
3. Создать новую ревизию с:
   - `valid_from` = дата_изменения
   - `mod_type` = "delete"
   - `modified_by_id` = ID изменяющего НПА
   - `body` = пустой массив или содержимое старой ревизии
4. У родителя обновить ревизию с `mod_type = "change"` (удалён дочерний элемент)

### Важно:
- Элемент НЕ удаляется физически из JSON!
- Он помечается как недействительный через `valid_to`

## 4. Тип `new_redaction` (новая редакция)

### Условия применения:
- Полная замена содержимого элемента на новое
- Должен быть указан полный путь к элементу

### Пример:
```json
{
  "revision_number": "1",
  "structural_element": "Статья 3 часть 2",
  "type": "new_redaction",
  "description": "часть 2 изложить в следующей редакции: «Кандидаты, не заявившие о самоотводе, считаются избранными.»"
}
```

### Действие:
1. Найти элемент по `structural_element`
2. Установить `valid_to` активной ревизии = (дата_изменения - 1 день)
3. Создать новую ревизию с:
   - `valid_from` = дата_изменения
   - `mod_type` = "new_redaction"
   - `modified_by_id` = ID изменяющего НПА
   - `body` = массив блоков с новым HTML-содержимым
4. Для `head_revisions` (если меняется наименование) - аналогичная логика

### Особенности:
- Для наименования НПА: `structural_element = "Наименование"`, меняется `head_revision[0].npa_head`
- Для наименования статьи/главы: меняется `head_revisions` элемента
- Для префикса приложения: меняется `item_prefix_revisions`

## 5. Тип `change` (частичное изменение)

### Условия применения:
- Изменение части элемента (слова, предложения, абзац, строка таблицы)
- Не полная замена, а точечное изменение

### Пример:
```json
{
  "revision_number": "2",
  "structural_element": "Статья 3 часть 2",
  "type": "change",
  "description": "слова «не заявившие о самоотводе» заменить словами «не подписавшие заявление о самоотводе»"
}
```

### Действие:
1. Найти элемент по `structural_element`
2. Получить HTML текущей активной ревизии
3. Применить текстовые изменения по ответу агента этапа 4 (prompt4)
4. Создать новую ревизию с изменённым HTML
5. Заполнить `highlights` с координатами изменений

## 6. Специальные структурные элементы

### 6.1 Наименование НПА
```json
{
  "structural_element": "Наименование",
  "type": "change",
  "description": "в наименовании слова «общественного» исключить"
}
```

### 6.2 Преамбула
```json
{
  "structural_element": "Преамбула",
  "type": "new_redaction",
  "description": "преамбулу изложить в следующей редакции: «Настоящий Закон...»"
}
```

### 6.3 Приложение
```json
{
  "structural_element": "Приложение 1",
  "type": "new_redaction",
  "description": "приложение 1 изложить в следующей редакции: «<table>...</table>»"
}
```

## 7. Поля, общие для всех типов

| Поле | Обязательно | Описание |
|------|-------------|----------|
| `revision_number` | Да | Иерархия внутренних подпунктов изменяющего НПА |
| `structural_element` | Да | Полный путь к целевому элементу |
| `type` | Да | Тип изменения |
| `description` | Да | Описание изменения |
| `new` | Нет | Только для `add` - тип и номер нового элемента |
| `valid_from` | Нет | Дата вступления в силу (d.m.Y), иначе используется общая |

## 8. Правила построения structural_element

### Формат:
`[Приложение N таблица] [Раздел N] [Статья N] [часть N] [пункт N] [подпункт N] [абзац N]`

### Правила:
1. От высшего к низшему
2. Именительный падеж
3. Только арабские цифры (кроме римских в официальных обозначениях)
4. Без предлогов
5. Слова «предложение», «строка», «ячейка», «графа» НЕ включаются

### Примеры:
- `"Статья 3"`
- `"Статья 3 часть 2"`
- `"Приложение 1 таблица Раздел VI¹"`
- `"Приложение 2 Статья 3 пункт 19"`

## 9. Правила revision_number

- `null` - если в статье изменяющего НПА нет внутренней нумерации
- `"1)"` - первый подпункт статьи
- `"1)->а)"` - подпункт а) внутри подпункта 1)
- НЕ содержит номер статьи изменяющего НПА!
- НЕ содержит индексы изменений (1)->1, 1)->2)
